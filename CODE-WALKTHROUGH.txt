AQUAATLAS VIETNAM — GHI CHÚ HỌC CODE
=====================================

Tệp này dùng để học code và ghi lại các đợt cập nhật. README.md chỉ giới thiệu
website và cách chạy dự án.

2. REACT HOẠT ĐỘNG NHƯ THẾ NÀO?
-------------------------------

Component là một phần giao diện có thể đặt tên và tái sử dụng. Trong dự án,
SiteHeader là thanh điều hướng, HeroSection là ảnh bìa, SpeciesSection hiển thị
loài cá, còn SiteFooter là chân trang.

src/App.jsx đặt các component cạnh nhau để tạo trang. Ví dụ:

  <SiteHeader />
  <HeroSection />
  <SpeciesSection fish={visibleFish} />

Tên component viết hoa để React nhận ra đây là component. Các component nhỏ giúp
người học tìm đúng phần cần sửa, thay vì đọc một tệp chứa cả website.

Props là dữ liệu hoặc hàm component cha gửi cho component con. Ví dụ,
<SpeciesSection fish={visibleFish} onSelectFish={openFish} /> gửi danh sách cá
và hàm mở hồ sơ xuống component con.

useState lưu trạng thái có thể thay đổi khi người dùng thao tác. App.jsx lưu từ
khóa tìm kiếm, nhóm cá và độ khó đã chọn. FishCard lưu trạng thái yêu thích của
riêng thẻ đó. Khi state thay đổi, React tự cập nhật phần giao diện liên quan.

Dashboard dùng state để điền biểu mẫu và cập nhật danh sách cá. App.jsx là nơi
giữ danh sách chung để danh mục ngoài trang chủ cập nhật ngay sau khi admin lưu.

App.jsx dùng filter() trực tiếp để tính danh sách cá đang khớp với bộ lọc. Với
danh sách mẫu nhỏ, cách viết thẳng giúp code dễ đọc; chỉ nên thêm useMemo khi
việc tính toán thật sự nặng hoặc đã đo thấy ảnh hưởng hiệu năng.

map() lặp qua mảng và tạo một phần tử giao diện cho mỗi dữ liệu. Ví dụ,
fish.map(...) tạo một FishCard cho mỗi loài. Thuộc tính key={item.id} giúp React
nhận diện ổn định từng thẻ khi danh sách thay đổi.


3. MATERIAL UI (MUI)
--------------------

MUI là thư viện component giao diện cho React. Dự án dùng Button cho nút,
Select/MenuItem cho lựa chọn, Card cho thẻ cá, Chip cho nhãn độ khó, TextField
cho ô email và IconButton cho nút menu/yêu thích.

src/theme.js tạo theme chung. Theme đặt màu chính, màu nhấn, font, góc vuông và
kiểu mặc định cho nút. Khi muốn đổi màu hoặc cách hiển thị mặc định của MUI,
bắt đầu từ tệp này. src/styles.css tinh chỉnh để các component MUI khớp thiết kế
riêng của website.


4. DỮ LIỆU, BỘ LỌC VÀ HỒ SƠ CÁ
------------------------------

src/data/fish.js xuất một mảng các loài cá nước ngọt. Mỗi loài có id, tên thường
gọi, tên khoa học, nhóm cá, mức chăm sóc, thông số, ảnh và liên kết nguồn. Tách
dữ liệu khỏi giao diện giúp thêm cá mà không phải viết lại component.

Trong App.jsx, filter() tìm theo tên thường gọi hoặc tên khoa học rồi áp dụng bộ
lọc nhóm cá và độ khó. filter() không sửa mảng gốc; nó tạo danh sách kết quả mới
và truyền xuống SpeciesSection.

Để thêm cá, thêm một đối tượng mới vào src/data/fish.js và đặt id duy nhất. group
phải là tropical hoặc coldwater; level phải khớp với các giá trị trong lựa chọn
bộ lọc. Thêm nguồn để người đọc kiểm tra thông tin.

Khi người dùng mở hồ sơ, App.jsx thêm mã loài vào URL, ví dụ ?fish=betta, rồi
hiển thị FishDetailPage. Người dùng có thể tải lại hoặc chia sẻ URL đó. Sự kiện
Back của trình duyệt cũng đọc URL và đưa giao diện về đúng trang.


5. GIAO DIỆN VÀ RESPONSIVE
--------------------------

src/styles.css dùng className trong JSX để định dạng. Trong React, thuộc tính
className tương đương thuộc tính class trong HTML.

Các biến màu trong :root như --ink, --green và --lime giữ màu dùng chung. Đổi
giá trị biến để đổi màu ở nhiều khu vực cùng lúc.

@media (max-width: 720px) chứa các điều chỉnh cho điện thoại: menu chuyển thành
menu mở/đóng, lưới cá thành một cột và các khu vực xếp theo chiều dọc.

Theme MUI xử lý kiểu mặc định cho component thư viện; CSS riêng xử lý bố cục
thương hiệu. Tách hai phần này giúp tránh phải viết lại toàn bộ kiểu dáng của
các component MUI.


6. CHẠY DỰ ÁN
-------------

Sau khi cài Node.js, mở Terminal tại thư mục dự án và chạy:

  npm install
  npm run dev

npm install tải các thư viện được khai báo trong package.json. npm run dev khởi
động máy chủ phát triển Vite; mở địa chỉ localhost mà Terminal in ra để xem web.

Khi cần tạo phiên bản triển khai, chạy:

  npm run build

Vite sẽ đóng gói các tệp cần thiết vào thư mục dist/. Thư mục node_modules/ và
dist/ được bỏ qua bởi Git qua .gitignore; không cần đưa chúng lên GitHub.

    Đây chỉ là ví dụ học tập, không phải cách xác thực tài khoản an toàn.
  - App lưu phiên đăng nhập trong sessionStorage nên giữ trạng thái qua tải lại tab,
    nhưng kết thúc phiên trình duyệt thì người dùng cần đăng nhập lại.

Điều cần hiểu / giới hạn:
  - Tài khoản khách chỉ tồn tại trong trình duyệt hiện tại; chưa đăng nhập được
    trên thiết bị khác, chưa có email xác minh hoặc khôi phục mật khẩu.
  - Vì toàn bộ app là frontend tĩnh, người dùng có thể xem/sửa mã hoặc dữ liệu lưu.
    Hash mật khẩu và role check ở trình duyệt không đủ bảo vệ hệ thống công khai.
  - Muốn vận hành thật, cần máy chủ quản lý tài khoản, lưu dữ liệu trong database,
    xác thực phiên/token phía server và kiểm tra role trên từng API.


8. MẪU CHO CÁC BẢN TIẾP THEO

Thêm bản cập nhật mới ngay phía trên các bản cũ. Ghi điều người dùng nhìn thấy,
tệp thay đổi, cách code hoạt động và những giới hạn còn lại.

BẢN X — tên thay đổi — ngày/tháng/năm

Đã làm:
  - Mô tả tính năng hoặc thay đổi giao diện.

Điều cần hiểu / giới hạn:
