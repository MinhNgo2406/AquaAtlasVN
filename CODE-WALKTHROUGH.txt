Code liên quan:
  - `frontend/src/data/fish.js` là nguồn hồ sơ mặc định dùng bởi trang React.
    Mỗi object có mã `id`, tên thường gọi, tên khoa học, điều kiện bể, chăm sóc,
    ảnh và `sources` để người đọc kiểm tra thông tin.
  - `backend/db/seeds/fish.json` là bản JSON tương ứng cho database mới. Khi bảng
    fish còn trống backend nạp các hồ sơ này; seed không ghi đè nội dung admin.
  - `backend/db/migrations/003_add_freshwater_species.sql` thêm bốn loài vào
    database đã có dữ liệu. Bảng `schema_migrations` đánh dấu bản cập nhật đã
    chạy, để lần khởi động sau không thêm lại loài mà admin đã xóa.
  - `backend/db/migrations/004_correct_image_attributions.sql` sửa nhãn giấy phép
    của hai ảnh sau khi đối chiếu trang Commons. Nó chỉ đổi nhãn khi URL ảnh vẫn
    khớp ảnh Commons tương ứng; ảnh do admin thay sẽ không bị ảnh hưởng.
  - Migration chỉ sửa ảnh của sáu hồ sơ cũ nếu URL trong database vẫn đúng bằng
    URL mẫu cũ. Nếu admin đã thay ảnh, câu `WHERE` không khớp nên ảnh riêng được
    giữ nguyên.
  - `FishDetailPage.jsx` hiển thị `imageCredit`/`imageSource`; khi video đang
    chạy, nó vẫn hiện ghi công video như trước. `AdminDashboard.jsx` có trường
    để nhập/xem lại nguồn ảnh và nhãn nhóm hiển thị.

Cách hoạt động:
  - Backend đọc file migration 003 mỗi lần khởi động. SQL kiểm tra version trong
    `schema_migrations`; chỉ lần đầu mới thêm cá và sửa các ảnh mặc định.
  - JSON hồ sơ cá được lưu nguyên object trong cột JSONB. Vì vậy các trường ghi
    công mới đi cùng hồ sơ mà không cần thêm cột PostgreSQL.
  - Ảnh Commons được tải trực tiếp từ Wikimedia qua `Special:FilePath`. Nếu chủ
    ảnh đổi tệp hoặc nguồn không truy cập được, trang có thể không tải ảnh; liên
    kết ghi công cho phép kiểm tra trang gốc.

Điều cần hiểu / giới hạn:
  - OATA cung cấp ngưỡng tham khảo chung theo nhóm. Cá bắt tự nhiên, cá từ trại
    khác nhau hoặc từng biến thể có thể cần điều kiện khác; hãy hỏi cửa hàng và
    theo dõi chất lượng nước trước khi thả cá.
  - Ảnh có CC BY hoặc CC BY-SA cần giữ ghi công theo giấy phép. Đọc điều khoản
    trên trang Commons trước khi phân phối lại hoặc chỉnh sửa.
  - Bước này thêm ảnh tĩnh có nguồn cho bốn loài mới. Video động riêng cho từng
    loài mới chưa được thêm nếu chưa tìm được clip xác nhận đúng loài và giấy
    phép rõ ràng; website tiếp tục hiện ảnh tĩnh thay cho video.

2. REACT HOẠT ĐỘNG NHƯ THẾ NÀO?
-------------------------------

Component là một phần giao diện có thể đặt tên và tái sử dụng. Trong dự án,
SiteHeader là thanh điều hướng, HeroSection là ảnh bìa, SpeciesSection hiển thị
loài cá, còn SiteFooter là chân trang.

frontend/src/App.jsx đặt các component cạnh nhau để tạo trang. Ví dụ:

  <SiteHeader />
  <HeroSection />
  <SpeciesSection fish={visibleFish} />

Tên component viết hoa để React nhận ra đây là component. Các component nhỏ giúp
người học tìm đúng phần cần sửa, thay vì đọc một tệp chứa cả website.

Props là dữ liệu hoặc hàm component cha gửi cho component con. Ví dụ,
<SpeciesSection fish={visibleFish} onSelectFish={openFish} /> gửi danh sách cá
và hàm mở hồ sơ xuống component con.

useState lưu trạng thái có thể thay đổi khi người dùng thao tác. App.jsx lưu từ
khóa tìm kiếm, nhóm cá và độ khó đã chọn. FishCard lưu trạng thái yêu thích của
riêng thẻ đó. Khi state thay đổi, React tự cập nhật phần giao diện liên quan.

Dashboard dùng state để điền biểu mẫu và cập nhật danh sách cá. App.jsx là nơi
giữ danh sách chung để danh mục ngoài trang chủ cập nhật ngay sau khi admin lưu.

App.jsx dùng filter() trực tiếp để tính danh sách cá đang khớp với bộ lọc. Với
danh sách mẫu nhỏ, cách viết thẳng giúp code dễ đọc; chỉ nên thêm useMemo khi
việc tính toán thật sự nặng hoặc đã đo thấy ảnh hưởng hiệu năng.

map() lặp qua mảng và tạo một phần tử giao diện cho mỗi dữ liệu. Ví dụ,
fish.map(...) tạo một FishCard cho mỗi loài. Thuộc tính key={item.id} giúp React
nhận diện ổn định từng thẻ khi danh sách thay đổi.


3. MATERIAL UI (MUI)
--------------------

MUI là thư viện component giao diện cho React. Dự án dùng Button cho nút,
Select/MenuItem cho lựa chọn, Card cho thẻ cá, Chip cho nhãn độ khó, TextField
cho ô email và IconButton cho nút menu/yêu thích.

frontend/src/theme.js tạo theme chung. Theme đặt màu chính, màu nhấn, font, góc vuông và
kiểu mặc định cho nút. Khi muốn đổi màu hoặc cách hiển thị mặc định của MUI,
bắt đầu từ tệp này. frontend/src/styles.css tinh chỉnh để các component MUI khớp thiết kế
riêng của website.


4. DỮ LIỆU, BỘ LỌC VÀ HỒ SƠ CÁ
------------------------------

frontend/src/data/fish.js xuất một mảng các loài cá nước ngọt. Mỗi loài có id, tên thường
gọi, tên khoa học, nhóm cá, mức chăm sóc, thông số, ảnh và liên kết nguồn. Tách
dữ liệu khỏi giao diện giúp thêm cá mà không phải viết lại component.

Trong App.jsx, filter() tìm theo tên thường gọi hoặc tên khoa học rồi áp dụng bộ
lọc nhóm cá và độ khó. filter() không sửa mảng gốc; nó tạo danh sách kết quả mới
và truyền xuống SpeciesSection.

Để thêm cá, thêm một đối tượng mới vào frontend/src/data/fish.js và đặt id duy nhất. group
phải là tropical hoặc coldwater; level phải khớp với các giá trị trong lựa chọn
bộ lọc. Thêm nguồn để người đọc kiểm tra thông tin.

Khi người dùng mở hồ sơ, App.jsx thêm mã loài vào URL, ví dụ ?fish=betta, rồi
hiển thị FishDetailPage. Người dùng có thể tải lại hoặc chia sẻ URL đó. Sự kiện
Back của trình duyệt cũng đọc URL và đưa giao diện về đúng trang.


5. GIAO DIỆN VÀ RESPONSIVE
--------------------------

frontend/src/styles.css dùng className trong JSX để định dạng. Trong React, thuộc tính
className tương đương thuộc tính class trong HTML.

Các biến màu trong :root như --ink, --green và --lime giữ màu dùng chung. Đổi
giá trị biến để đổi màu ở nhiều khu vực cùng lúc.

@media (max-width: 720px) chứa các điều chỉnh cho điện thoại: menu chuyển thành
menu mở/đóng, lưới cá thành một cột và các khu vực xếp theo chiều dọc.

Theme MUI xử lý kiểu mặc định cho component thư viện; CSS riêng xử lý bố cục
thương hiệu. Tách hai phần này giúp tránh phải viết lại toàn bộ kiểu dáng của
các component MUI.


6. CHẠY DỰ ÁN
-------------

Sau khi cài Node.js, mở Terminal tại thư mục dự án và chạy:

  Terminal 1:
  cd backend
  npm start

  Terminal 2:
  cd frontend
  npm install
  npm run dev

npm start khởi động API. npm install tải thư viện React được khai báo trong
frontend/package.json. npm run dev khởi động Vite; mở địa chỉ localhost mà
Terminal in ra để xem website. Vite chuyển tiếp yêu cầu /api đến cổng 3000.

Để chạy hai phần bằng Docker, mở Docker Desktop rồi từ thư mục gốc chạy:

  docker compose up --build

Mở http://localhost:8080. Docker build frontend thành tệp tĩnh, Nginx phục vụ
trang và chuyển tiếp /api/ tới backend. PostgreSQL tạo bảng users và lưu dữ liệu
trong named volume `aqua_atlas_db_data`. Nhấn Ctrl+C để dừng; `docker compose down`
xóa container và network nhưng giữ volume dữ liệu. Chỉ dùng `docker compose down -v`
khi chủ ý xóa database local.

Để chỉ build frontend, chạy `npm run build` bên trong frontend/. Tệp đầu ra nằm
trong frontend/dist/. node_modules/, dist/ và .env bị bỏ qua bởi Git.

  - Cookie và truy vấn được thiết kế cho ứng dụng cùng origin. Trước khi triển
